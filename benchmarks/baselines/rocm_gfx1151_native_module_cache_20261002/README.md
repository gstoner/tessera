# gfx1151: native module-cache attribution

Owner: E2E-REAL-6-ROCM-MATMUL-CACHE / E2E-REAL-6-ROCM-CACHE-KEYS.
Sync: ROCM-NATIVE-MODULE-CACHE-2026-10-02.
Owning device: AMD Radeon(TM) 8060S Graphics; live and configured architecture both gfx1151.

## Native contract and proof

Compiler-owned Graph -> Schedule -> Tile -> ROCm Target -> ROCDL/LLVM -> HSACO
is retained. Target identity projection runs in MLIR. The checked descriptor
validates every call, including image/entry ABI, shape capacities, dtype and
layout. A native cache hit does not replace those checks.

The new C++ HIP image service keys actual complete image bytes by current
device, context, architecture and process. It owns module and function handles
through an opaque lease held until the checked launch synchronizes. Inactive
entries are evicted under their owning context. Each context retains at most
16 modules and 32 MiB of image payloads; overflow requests execute with an
uncached temporary lease. Explicit clear rejects outstanding leases. No HIP
unload runs from a C++ process-exit destructor.

The private host ABI exports acquire, lookup, release, clear-current and
statistics. Its status values are 1 malformed request, 2 process/context
identity, 3 module load, 4 symbol lookup, 5 active lease, 6 unload failure, and
7 host allocation/exception. Callers must complete launches before releasing
leases and clear before external context destruction/device reset. The native
API refuses inherited process ownership. This does not claim general HIP
execution support after fork or automatic handling of external resets.

Python binds this service and passes compiler-generated bytes/entry names;
it owns no new module cache, cache identity algorithm or generated kernel.
A built runtime is discovered through TESSERA_ROCM_NATIVE_IMAGE_LIB,
TESSERA_BUILD_DIR or the selected TESSERA_OPT build. An explicit invalid library
path errors. TESSERA_ROCM_NATIVE_IMAGE_CACHE=0 uses the established per-call HIP
loader for attribution; disabling acquisitions does not hide explicit clearing
of already retained modules.

[Exact-device validation](validation-tests.txt): 61 passed, three sibling-architecture
cases skipped. This includes fp16/bf16 static/dynamic/fused numerical cases,
real native projection, a hot-cache over-capacity refusal before acquisition,
and native context/device/lifetime/concurrency/eviction tests against a
controlled HIP ABI. Device/context-switch and fork tests use the controlled ABI;
no multi-GPU hardware claim is inferred. Eight timing packets use fp16.

## Matched attribution

Each row below compares the same six shapes, identical compiled image digests
and symbols, identical numerical inputs/oracles, register staging, k-unroll one
and split-K one. Each arm executes five numerical warmups and eleven checked
timing samples per shape. In every cached arm native counters report one module
load, 95 hits, one function lookup and zero unloads during the measured envelope.
Every uncached arm records 96 per-call module loads. Source and library hashes
are in the raw packets; validation.json seals all files.

The ratio applies to instrumented runtime.launch end-to-end calls, not kernel
throughput. HIP event intervals bracket each launch on the default stream and
can include dispatch gaps for these short kernels. Event synchronization also
appears in the instrumented E2E interval. Host/device allocation, copies,
validation and dispatch still occur on every call. Clocks are uncontrolled and
some event rows are noisy; raw samples are retained. No kernel speedup or
selector promotion is claimed.
